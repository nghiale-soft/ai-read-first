# Versioning Standards

Use project-defined versioning. When Semantic Versioning applies:

```text
MAJOR.MINOR.PATCH
```

- MAJOR: breaking change
- MINOR: backward-compatible feature
- PATCH: backward-compatible fix

Do not silently change the meaning of an existing API, field, event, or stored document.

A release should document:

- version or tag
- behavior changes
- migration
- breaking changes
- rollback considerations
